Desfase objeto-relacional

Con JDBC puro hay que convertir a mano cada fila en un objeto y cerrar los recursos. Es código largo y repetitivo.

Java · JDBC
PreparedStatement ps = con
    .prepareStatement("SELECT * FROM empleados WHERE id = ?");
ps.setInt(1, id);
ResultSet rs = ps.executeQuery();
Empleado result = null;
if (rs.next()) {
    result = new Empleado(rs.getInt("id"),
        rs.getString("nombre"),
        rs.getString("apellidos"),
        rs.getDate("fecha_nacimiento").toLocalDate(),
        rs.getFloat("sueldo"));
}
rs.close();
ps.close();
return result;

Entidad

Es un concepto del «mundo real». Sus características son la identidad, los atributos y las asociaciones.

Mapeo de entidad a tabla

Entidad Contacto

Propiedades: id, nombre, apellidos, email, teléfono.

Columnas: id, nombre, apellidos, email, teléfono.

Entidad frente a valor

Entidad

Tiene identificador único y ciclo de vida.

Valor

Sin identificador ni ciclo de vida propio. Tipos: basic, embedded, collection.

Requisitos para ser entidad

  • Llevar @Entity.
  • Constructor sin argumentos.
  • Ser una clase de nivel superior (top-level).
  • No puede ser enum, interface ni record.
  • No puede ser final.
  • Tener un identificador.
  • equals() y hashCode() consistentes.

Cosas que admite o deja abiertas:

  • ¿Serializable? Opcional.
  • Puede ser abstracta o concreta.
  • Puede extender de otra entidad o no.
  • Getters y setters.

Nuestra primera entidad

  • Clase Producto.
  • Algunos atributos básicos.
  • Métodos generados con Lombok.

equals y hashCode

Métodos equals y hashCode.pdf

Qué hace cada uno

equals
dice si dos objetos son iguales
hashCode
devuelve el código hash de un objeto

¿Dónde está el problema?

  • Las instancias de entidad representan filas.
  • Dos filas son iguales si lo son sus claves primarias.
  • Por tanto, dos objetos son iguales si lo son sus ID.

Dos propuestas: ChatGPT y Thorben Janssen

El equals es el mismo en ambas. Cambia el hashCode.

ChatGPT
return Objects.hash(id);
Thorben Janssen
return 13;

Una buena aproximación

Java · entidad Student
@Getter
@Setter
@Entity
@Table(name = "student")
public class Student {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "id", nullable = false)
    private Long id;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Student other = (Student) o;
        return id != null && id.equals(other.getId());
    }

    @Override
    public int hashCode() {
        return getClass().hashCode();
    }
}

La definitiva

Que lo haga JPA Buddy. Si usas @Data de Lombok en una entidad JPA, avisa de que no se recomienda por problemas graves de rendimiento y consumo de memoria. Ofrece sustituirlo por anotaciones seguras con equals() y hashCode() autogenerados.
